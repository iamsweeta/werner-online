# Проверка 56.0 · OCR одного маршрута

## Найденная причина лишней работы

В версии 55.0 импорт одного направления вызывал OCR всех числовых строк прайса. Прогресс сообщался только при переходе к следующей странице: чтение заголовка, двух вариантов цифр и повторные проверки спорных ячеек оставались под одним сообщением «страница 1». Это подтверждено кодом. Точную причину пяти минут на сервере пользователя без его журналов и характеристик установить нельзя.

В 56.0 для одного маршрута сначала читаются названия городов и проверяется единственный результат, затем распознаётся только его строка. Общая библиотека сохраняет режим полного документа. Полный результат может обслужить несколько направлений в одной сессии; частичный кэш не подменяет полный документ или другое направление. Цифры по-прежнему требуют совпадения двух чтений. Новые константы тарифных цен не добавлены.

## Пользовательский PDF и настоящий HTTP

Исходный dsjf.pdf, 9 страниц, 4,5 МБ, без текстового слоя. Протестированы настоящий Uvicorn, фоновое задание, настоящий OCR, подтверждение, общая библиотека, скачивание оригинала и Excel отдельного направления. Для загрузки, опроса состояния и /health установлен лимит 1 секунда на HTTP-запрос.

| Проверка | Результат |
|---|---|
| Направление | Санкт-Петербург → Москва |
| Приём файла | HTTP 202, 0,500 с |
| Максимальное время запроса статуса | 0,330 с; 52 опроса |
| Весь сценарий, включая сохранение и Excel | 56,84 с |
| Предыдущая проверка 55.0 на том же документе | 250,23 с; исторический результат |
| Числа исходной строки | Все 20 совпали; страница 3 |
| Выходные диапазоны | 28; нет выдуманного диапазона 20 000 кг |
| Контроль | До 1 кг — 610 ₽; 100 кг — 1490 ₽ |
| Оригинал | Скачан побайтно без изменения |
| Excel | Отдельный файл, листы «Маршрут» и «Источники» |

Это измерения в среде проверки, не обещание того же времени на другом сервере. Тарифные значения в отчёте — контроль исходного документа, а не заявка на актуальность на сегодня и не рабочие константы приложения.

## Автоматические проверки

16 Python-тестов — PASS: реальный повёрнутый растровый PDF в полном и выборочном режимах, точное название/перенос/дубликаты, изоляция кэша, убийство зависшего OCR-процесса, отсутствие внешнего Tesseract, строгие числа, библиотека и Excel, асинхронный приём, повторные запросы без новой загрузки, межпроцессное чтение результата, явное подтверждение, прерывание, истечение, лимит заданий, прогресс и резервная копия.

10 UI-наборов — PASS: добавлены проверки общего времени и сообщения о долгом этапе. Прежние проверки временной 502, потери ответа загрузки, восстановления окна, выбора документов, экспорта, тем и графиков проходят.

## Полный документ и границы строки

Полный OCR того же пользовательского PDF: **220 направлений, 6160 значений, 0 ошибок**. Все суммы и ставки каждого диапазона сопоставлены с результатом проверенного импорта 54.0 — совпадают. Дополнительно узким фрагментом прочитаны «Переславль-Залесский» (название с переносом) и «Ярославль» (последняя строка): по 20 чисел совпали с полным чтением. Сценарий полного OCR и этих дополнительных проверок занял 221,85 с.

## Контроль долгих этапов

Каждое OCR-чтение публикует этап с отдельным порядковым номером. Если этап не заканчивается за 120 секунд, родитель останавливает дочерний OCR-процесс и возвращает объяснение; обычный heartbeat фонового задания таймер не сбрасывает. Сторожевой таймер работает и без слушателя прогресса. Общий лимит OCR остаётся 600 секунд. При ошибке цена не применяется и последняя сохранённая цена не удаляется.

## Применение и границы

Работающий сервер пользователя в этой проверке не обновлялся. Архив нужно установить, сохранив прежний каталог данных, перезапустить сервер и обновить страницу браузера. Незавершённый файл загрузить заново. Улучшение не меняет ограничения памяти/CPU хостинга и не восстанавливает вычисление после полного перезапуска сервера.
