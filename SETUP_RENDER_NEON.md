# Версия 63: Render Free + Neon

Пошаговая настройка хранения цен и прайс-листов отдельно от сервера приложения.
Проверено по документации провайдеров 28 сентября 2026 года.

## Что получится

Сайт и распознавание документов работают на Render. PostgreSQL в Neon хранит цены, маршруты, ручные изменения, библиотеку и результаты большой таблицы. Закрытый бакет Neon Object Storage хранит оригиналы и готовые большие Excel. После перезапуска Render приложение читает те же данные из облака. Повторно загружать подтверждённые прайсы не требуется.

В бесплатном плане Neon на эту дату включены 0,5 ГБ PostgreSQL, 5 ГБ файлов и 100 CU-часов вычислений базы в месяц. Это лимиты, а не обещание бесплатной работы при любой нагрузке. Следите за Usage в Neon, особенно при сборе «Всех пар городов» и накоплении истории. Условия могут измениться.

Render Free засыпает после 15 минут без входящих обращений; открытие после простоя может занимать около минуты. Длительное OCR по-прежнему ограничено CPU и памятью Render. Подключение внешней базы не превращает бесплатный сервер в постоянно работающий мощный сервер. Прерванный общий сбор продолжается кнопкой «Продолжить»; прерванное OCR можно повторить из принятого файла, пока не истёк предпросмотр.

## 0. Сначала сохранить данные со старого сайта

**Сделайте это до обновления кода, изменения тарифа, переменных или перезапуска Render.**

1. Откройте действующий сайт → **Прайс-листы**.
2. Нажмите **Скачать резервную копию данных**.
3. Сохраните `tariff_data_backup.zip` на своём компьютере. Не удаляйте его после переноса.
4. Запишите один известный маршрут, компанию и цену для контрольной проверки.

В версии 62 резервная копия содержит документы, распознанные, ручные и онлайн-цены, выбор источников и историю большой таблицы. Копии старых версий могут содержать только документы и ручные цены: отсутствующие в архиве данные перенос не создаст. Секретные API-ключи перевозчиков и временные предпросмотры не включаются. Если старые данные уже исчезли и копии нет, нужно заново загрузить исходные прайсы.

## 1. Распаковать приложение на компьютере

1. Распакуйте `tariff_app_63_2.zip` целиком.
2. Откройте папку `TARIFF_APP_V63_2`. В ней находятся `app`, `static`, `data`, `requirements.txt`, `configure_neon.py` и эта инструкция.
3. Для помощника настройки нужен Python 3.11 или новее. На Windows при установке Python включите **Add Python to PATH**. Если приложение уже запускалось на компьютере, Python, вероятно, установлен.

**Не загружайте ZIP приложения в раздел прайс-листов:** там принимаются документы перевозчиков. Код приложения отправляется в GitHub, а резервная копия — в отдельную форму переноса после настройки.

## 2. Создать бесплатный проект Neon

1. Откройте [Neon](https://console.neon.tech/) и войдите/зарегистрируйтесь.
2. Создайте проект, например `tariff-app`. Выберите **Free**.
3. Провайдер: **AWS**. Регион: **Europe (Frankfurt), eu-central-1**. Этот регион поддерживает и PostgreSQL, и Object Storage. Для сервиса Render по возможности используйте Frankfurt, чтобы уменьшить задержку.
4. Используйте одну рабочую ветку, обычно **main**, и одну базу, обычно **neondb**. Запомните выбранную ветку. Не удаляйте и не пересоздавайте её при ежемесячном обновлении прайсов.
5. В проекте нажмите **Connect**. Выберите нужную ветку и базу. Включите **Connection pooling**, если переключатель доступен.
6. Скопируйте полную connection string: она начинается с `postgresql://` и содержит `sslmode=require` (возможен дополнительный `channel_binding=require`). Нужна сама строка, без `psql`, без внешних кавычек. Сохраните её временно в надёжном месте.
7. Для помощника настройки создайте **Neon API key** в настройках учётной записи / организации → **API keys**. Дайте ему доступ к выбранному проекту. Этот служебный ключ нужен только для создания закрытого файлового бакета и отдельного ключа Storage. Он не будет записан в приложение или Render.

## 3. Подготовить хранилище и файл настроек

Проще всего воспользоваться помощником из архива.

**Windows**

Дважды откройте `SETUP_CLOUD_WINDOWS.cmd`. Он установит библиотеку `requests` и запустит помощник. Если окно пишет, что Python не найден, установите Python с опцией Add Python to PATH и откройте командный файл снова.

**macOS / Linux**, из папки приложения:

```bash
python3 -m pip install requests
python3 configure_neon.py
```

Дальше во всех системах:

1. Вставьте connection string PostgreSQL из шага 2. При вводе символы скрыты — это нормально. Нажмите Enter.
2. Вставьте служебный Neon API key. Ввод также скрыт.
3. Из списка выберите номер проекта `tariff-app`.
4. Выберите номер рабочей ветки **main** или вашей выбранной ветки.
5. Помощник создаст новый **private**-бакет `tariff-prices-…`, отдельный ключ с правами чтения/записи Storage и файл **`render.env`** рядом с приложением.
6. Откройте `render.env` в обычном текстовом редакторе. В нём заполнены настройки Render и APP_AUTH_MODE=public для свободного входа. Также создан пароль для возможного перехода в закрытый режим.

**`render.env` содержит пароли. Не добавляйте его в GitHub, не прикладывайте в чат и не отправляйте заказчику вместе с исходниками.** В проекте есть `.gitignore`, но при ручной загрузке через браузер нужно самому исключить этот файл. Сделайте закрытую копию настроек у себя.

Если `render.env` уже существует, помощник не перезапишет его. Для повторной настройки сначала сохраните прежний файл отдельно. Каждая успешная новая настройка создаёт отдельный бакет и ключ: не запускайте её ежемесячно. После успешной проверки сайта служебный API key для помощника можно отозвать; **S3-ключ, указанный в `render.env`, отзывать нельзя**, пока он используется приложением.

### Если настраивать вручную

В Neon → проект → выбранная ветка → **Object storage** → **New bucket** создайте бакет с доступом **private**. Получите Storage endpoint, регион и отдельные S3-учётные данные по [официальной инструкции](https://neon.com/docs/storage/get-started). Не путайте пароль базы, Neon API key и S3 secret key — это разные значения.

| Переменная Render | Что указать |
|---|---|
| `TARIFF_STORAGE` | `cloud` |
| `DATABASE_URL` | Полная PostgreSQL connection string с `sslmode=require` |
| `S3_ENDPOINT_URL` | Полный `s3_endpoint` ветки Neon; не адрес консоли, без имени бакета |
| `S3_REGION` | Регион Storage из Neon, например `eu-central-1` |
| `S3_BUCKET` | Имя закрытого бакета |
| `S3_ACCESS_KEY_ID` | `token_id` ключа Storage; аналог `AWS_ACCESS_KEY_ID` |
| `S3_SECRET_ACCESS_KEY` | `s3_secret_access_key`; аналог `AWS_SECRET_ACCESS_KEY` |
| `S3_PREFIX` | `tariff-app`; впоследствии не менять |
| `APP_AUTH_MODE` | `public` — общий доступ без пароля; `password` — вход по паролю |
| `APP_USERNAME` | `manager` |
| `APP_PASSWORD` | Пароль не менее 12 символов для APP_AUTH_MODE=password; в public не используется |
| `TARIFF_DATA_DIR` | `./runtime` — временный локальный кэш, постоянные данные находятся в облаке |
| `PYTHON_VERSION` | `3.12.11` |

Если Neon Storage недоступен в вашем регионе, создайте проект в поддерживаемом AWS-регионе. Приложение также поддерживает другие S3-совместимые хранилища (например, R2), но у них собственные лимиты и условия оплаты. В этом руководстве используется Neon.

## 4. Загрузить код в GitHub

Если Render уже связан с репозиторием приложения, обновите **тот же репозиторий**. Убедитесь, что резервная копия из шага 0 уже скачана: автоматическое развёртывание может начаться сразу после коммита. По возможности временно выключите Auto-Deploy в настройках сервиса.

1. Откройте репозиторий GitHub. Для нового проекта создайте **Private repository**.
2. Загрузите **содержимое** папки `TARIFF_APP_V63_2`, а не ZIP и не дополнительную внешнюю папку. Если загружаете через браузер: **Add file → Upload files**. Перенесите `app`, `static`, `data` и файлы в корне.
3. В корне репозитория должны быть `requirements.txt`, `render.yaml`, `app/`, `static/`, `data/`. Обязательно сохраните `data/ocr` и `data/export_template.xlsx`.
4. Не загружайте `runtime`, `.env`, `render.env`, резервные копии, виртуальные окружения и свои прайсы.
5. Сделайте commit.

Таблицы в PostgreSQL создаются приложением автоматически. SQL вручную выполнять не нужно. Цены не берутся из шаблона Excel: он используется для структуры и оформления.

## 5. Настроить Render

### Уже есть сайт на Render

1. Откройте [Render Dashboard](https://dashboard.render.com/) → существующий Web Service.
2. В **Settings** проверьте привязанный репозиторий и ветку с версией 63.
3. **Root Directory**: пусто, если `requirements.txt` лежит в корне репозитория. Если сохраняете внешнюю папку, укажите фактический путь к ней.
4. **Build Command**:

```bash
pip install -r requirements.txt
```

5. **Start Command**:

```bash
python -m uvicorn app.v42_main:app --host 0.0.0.0 --port $PORT --workers 1
```

6. **Health Check Path**: `/health`. Используйте один процесс и один экземпляр приложения.
7. **Environment → Add from .env**: вставьте содержимое локального `render.env`. Если этой кнопки нет, добавьте каждую переменную из таблицы вручную. Не вводите внешние кавычки как часть значения при ручном добавлении.
8. Сохраните настройки и выполните **Manual Deploy → Deploy latest commit**. Дождитесь **Live**.
9. Если был настроен Persistent Disk: **не удаляйте его до успешного переноса и проверки резервной копии**. При необходимости сначала разверните новый Free Web Service с тем же кодом и внешним облаком, проверьте данные, затем решайте судьбу старого сервиса. Платный сервис с диском не превращается в Free только из-за нового `render.yaml`.

### Создаёте новый сервис

**New → Web Service** → подключите GitHub-репозиторий → Runtime **Python 3**, Instance Type **Free**. Задайте команды и переменные выше. Постоянный диск не требуется. Можно использовать Blueprint из `render.yaml`, но для обычной ручной настройки он необязателен.

## 6. Первый вход и проверка облака

1. Откройте адрес приложения `https://…onrender.com`.
2. При APP_AUTH_MODE=public сайт открывается без пароля. Все посетители могут просматривать и менять общие цены и файлы. Если выбран password, браузер запросит APP_USERNAME и APP_PASSWORD из Render Environment.
3. Откройте **Прайс-листы → Хранилище: проверка подключения и перенос резервной копии**. Прямая ссылка — адрес вашего сайта + `/storage-guide`.
4. Нажмите **Проверить базу и файлы**. Должно появиться сообщение об успешной записи и чтении пробного файла.
5. В «Прайс-листах» должен отображаться статус **Облачное хранение**. Если увидите предупреждение о локальном диске, `TARIFF_STORAGE=cloud` не применился.

**Не начинайте загружать новые прайсы или вводить цены, если собираетесь переносить резервную копию:** перенос специально разрешён только в пустую базу.

## 7. Перенести старую резервную копию

На странице `/storage-guide`:

1. Выберите сохранённый `tariff_data_backup.zip`.
2. Нажмите **Перенести резервную копию**.
3. Не закрывайте страницу до сообщения **Архив принят**. Затем идёт фоновая проверка и перенос; статус обновляется на этой странице.
4. Дождитесь **Перенос завершён**.
5. Откройте известный маршрут. Данные из файла и ручные цены должны появиться без онлайн-обновления.
6. В большой таблице выберите **Собрать Excel из сохранённых цен**. Перенесённые старые готовые Excel пересоздаются: резервная копия содержит цены и историю, а не сами выгрузки.

Если Render перезапустился, откройте `/storage-guide` снова и нажмите **Продолжить перенос сохранённого архива**, когда кнопка появится. Перенос записывает цены одной транзакцией: либо весь набор подтверждён, либо прежняя база не меняется. Загруженные, но ещё не привязанные служебные объекты могут оставаться в бакете до обслуживания.

Сообщение **В облачной базе уже есть данные** защищает существующие цены. Не удаляйте их, чтобы обойти проверку. Используйте новый отдельный проект/базу и бакет для переноса либо оставьте текущие данные и добавляйте обычные прайсы через библиотеку.

Если данных раньше не было, этот шаг пропускается: загружайте документы как обычно в «Прайс-листы», проверьте распознавание и нажмите «Применить цены из файла».

### Крупная резервная копия или нестабильная связь с Render

Для ZIP больше 512 МБ или при проблемах HTTP перенесите данные напрямую с компьютера. Откройте терминал в папке приложения, где находится `render.env`:

```bash
python -m pip install -r requirements.txt
python cloud_setup.py check --env render.env
python cloud_setup.py migrate "C:/Users/YourName/Downloads/tariff_data_backup.zip" --env render.env
```

На macOS/Linux используйте `python3` и фактический путь. Лимит распакованной копии — 2 ГБ / 100 000 файлов. На время переноса не работайте с ценами в приложении. При недостаточном лимите Neon операция выдаст ошибку; не считайте перенос завершённым, пока не появилось `ok: true`.

## 8. Обязательная контрольная проверка

1. Найдите прежнюю цену в известном маршруте.
2. В библиотеке скачайте оригинальный PDF/XLSX/CSV — он должен открыться.
3. Скачайте Excel отдельного маршрута и большую таблицу из сохранённых цен.
4. Перезапустите сервис Render.
5. Откройте сайт снова. Проверьте ту же цену, оригинал и историю большой таблицы **без нового онлайн-сбора**.
6. Скачайте новую резервную копию и храните отдельно от облачных учётных данных.

## Как пользоваться дальше

- Прайсы обновляются по вашей кнопке. Новая неудачная онлайн-проверка не удаляет последние успешные цены; актуальность показывается отдельно.
- Один подтверждённый документ работает и для отдельных маршрутов, и для большой таблицы.
- Подтверждённые документы и цены не удаляются приложением через месяц. Их сохранность зависит также от сохранения аккаунта/проекта Neon и соблюдения лимитов провайдера.
- Отключение прайса убирает его из сравнения, но сохраняет оригинал. История занимает место; отслеживайте Usage.
- Неподтверждённый предпросмотр действителен 30 минут после распознавания. Прерванный OCR запускается заново из принятого файла, а не с точностью до последней строки страницы.
- Скачанный Excel сам не обновляется. После изменения данных скачайте новую версию.
- Не меняйте `DATABASE_URL`, бакет, ветку или `S3_PREFIX` без отдельного переноса. Подключение другого пустого проекта покажет пустую таблицу.
- Делайте резервную копию перед крупным обновлением и после ежемесячного импорта. Бесплатный тариф сам по себе не заменяет резервное копирование.

## Частые проблемы

| Симптом | Что проверить |
|---|---|
| Сайт не запускается, ошибка `APP_PASSWORD` | Установите APP_AUTH_MODE=public для свободного входа или пароль минимум 12 символов для password; выполните новое развёртывание |
| Ошибка базы / `DATABASE_URL` | Полная строка PostgreSQL, пароль, `sslmode=require`, правильная ветка, свободный лимит Neon |
| Цены видны, оригиналы недоступны | S3 endpoint, регион, имя бакета и отдельные Storage-ключи; выполните «Проверить базу и файлы» |
| Storage возвращает 404 при настройке | Выбрана поддерживаемая AWS-локация, например Frankfurt; проект/ветка существуют |
| После обновления всё пусто | Не подключён ли другой проект/ветка; выполнен ли перенос; установлен ли `TARIFF_STORAGE=cloud` |
| При первом открытии долго загружается | Render Free просыпается. Подождите около минуты |
| Общий сбор остановлен | Откройте его историю и нажмите «Продолжить»; подтверждённые результаты остаются |
| OCR прерван | Повторите распознавание сохранённого файла в интерфейсе. При истёкшем предпросмотре загрузите файл заново |
| Недостаточно места в Neon | Посмотрите Usage. Для большого числа историй/всех пар городов бесплатного лимита может не хватить |
| Перенос через сайт даёт 502 | Откройте страницу статуса снова; если нужно, используйте прямой перенос `cloud_setup.py` с компьютера |

## Локальный режим и обратный перенос

Без `TARIFF_STORAGE=cloud` приложение работает с локальной SQLite и папками, как раньше. Для локального восстановления облачной копии:

```bash
python restore_data.py tariff_data_backup.zip --target restored-data
```

Затем задайте `TARIFF_STORAGE=local`, `TARIFF_DATA_DIR` равным абсолютному пути к `restored-data`. На Render в локальном режиме нужен платный Persistent Disk. Если хотите облачную базу, не переключайтесь в local при ошибке подключения — это создаст отдельное хранилище и расхождение данных.

Это не проверка вашего живого аккаунта Neon или развёртывание на Render: финальную проверку реального подключения выполняет кнопка «Проверить базу и файлы» и шаг 8 после вашей настройки.
